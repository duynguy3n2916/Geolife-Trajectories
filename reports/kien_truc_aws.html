Kiến trúc Home/Office trên AWS

Từ GPS thô của GeoLife, hệ thống suy ra vị trí nhà và nơi làm việc cho từng user. Phần tính toán chạy theo lô trên Lambda, còn API chỉ đọc kết quả đã tính sẵn, nên trả lời nhanh và rẻ.

ap-southeast-1 (Singapore) 1 tài khoản AWS riêng model: heuristic-v1, dbscan-v2

Hai luồng chính

Batch: tính kết quả (offline)

Chạy khi có dữ liệu mới hoặc đổi ngưỡng
  1. Đưa GPS thô và ngưỡng của từng model lên S3.
  2. Từ máy dev, gọi Lambda batch, mỗi lần một cặp (user, model). Có thể gọi song song hoặc bất đồng bộ.
  3. Lambda đọc ngưỡng, tải GPS của user, chạy pipeline: lọc, tìm stay point, gom địa điểm, bỏ phiếu home/office.
  4. Ghi kết quả của user đó lên S3.

API: tra cứu (online)

Không chạy model, chỉ đọc file đã tính
  1. App gọi GET /v1/users/{user_id}/home-office, có thể kèm ?model_version=dbscan-v2.
  2. API Gateway giới hạn 20 request/giây rồi chuyển cho Lambda tra cứu.
  3. Lambda kiểm tra user_id và version, đọc file kết quả trên S3. Nếu không truyền version thì dùng version mặc định (cấu hình trên S3, đổi được mà không cần deploy lại).
  4. Trả JSON gồm toạ độ home/office, độ tin cậy, số phiếu, kèm header X-Model-Version.

Quản lý version model

  • Mỗi version model là một bộ ngưỡng riêng trên S3, kết quả của version nào nằm riêng thư mục của version đó.
  • API chọn version qua tham số model_version, mặc định theo một cấu hình trên S3.
  • Dự kiến: SageMaker Model Registry ghi lại 2 version, kèm con trỏ tới ngưỡng và kết quả, và đánh dấu version được duyệt. Registry không lưu file, chỉ lưu con trỏ và metadata.
  • Lambda tra cứu không gọi registry, nên API vẫn nhanh và không phụ thuộc thêm dịch vụ.

Bảo mật và độ tin cậy

  • Bucket chặn toàn bộ truy cập công khai.
  • Mỗi Lambda chỉ có quyền S3 cho đúng thư mục nó cần.
  • API kiểm tra user_id bằng regex để chặn chèn đường dẫn vào key S3. Log không ghi toạ độ.
  • Đã có công tắc AUTH_MODE=jwt trong code, hiện đang tắt.

Đo cold start của API (13/11/2026)

Lambda tra cứu đã nghỉ hơn 1 giờ trước lần đo. Gọi API 8 lần liên tiếp từ máy dev ở Việt Nam; số phía máy chủ lấy từ dòng REPORT trong CloudWatch Logs.

Cold start làm phía máy chủ chậm thêm khoảng 0,6 giây (khởi động Python và thư viện AWS, lần đọc S3 đầu tiên). Phần còn lại của 1,5 giây ở lần đầu chủ yếu là máy dev mở kết nối HTTPS mới. Khi đã ấm, mỗi lần tra cứu chỉ tốn khoảng 30 ms trên máy chủ, còn lại là đường mạng từ Việt Nam tới Singapore. Mức chậm này chấp nhận được với đồ án, nên không dùng lịch gọi định kỳ để giữ Lambda ấm. Trước khi demo, chỉ cần gọi /health một lần.
